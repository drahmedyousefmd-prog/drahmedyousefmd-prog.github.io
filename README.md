# Rochetta — دليل روشتات مصر

Practical medical prescription reference: for each condition, the suggested drug list, dosing instructions, alternative brands with prices, and drug interactions. Arabic-first (`lang="ar"`, `dir="rtl"`), static, and free to host.

**Live:** https://drahmedyousefmd-prog.github.io/

## Stack

- **Next.js 16** (App Router) · `output: "export"` — fully static site
- **React 19** + **TypeScript** (strict) + **ESLint** (`eslint-config-next`)
- **Tailwind CSS v4** (`@tailwindcss/postcss`) + a small design-token layer in `src/styles/`
- **lucide-react** icons · **next/font** Google Fonts (Cairo / Tajawal / Inter), self-hosted at build
- Data: plain JSON in `src/data/` — **no runtime API, no database**
- Deploy: GitHub Pages (`gh-pages` branch, `.nojekyll`)

## Data schema

`src/data/prescriptions.json` is the single source of truth. One record per condition:

```jsonc
{
  "id": "rochetta-001",
  "title": "Major Depressive Disorder",
  "subtitle": "…",
  "content": "[DIAGNOSIS]\n- …\n[RX-الروشتة — 1st line]\n- Drug (Generic) | جرعة | سعر ج.م",
  "category": "Psychiatry",            // must match a chapter name in src/lib/chapters.ts
  "chapterAr": "أعصاب / الطب النفسي",
  "perDrugAlternatives": "Drug: Alt | price, Alt2 | p2",
  "drugInstructions": "⚠️/✅/❌ lines",
  "drugInteractions": "blocks with ❌/⚠️"
}
```

The `content` parser lives in `src/lib/content.ts` (`parseContent`, `parseRxLines`, …). Do not change the parser's output semantics.

## Deploy

Deploy working copy lives outside the repo (so static-export noise doesn't pollute `main`):

```powershell
powershell -File scripts/deploy.ps1          # build, prune RSC .txts, push gh-pages
powershell -File scripts/deploy.ps1 -NoPush  # preview what would go live
```

GitHub Pages user-site requirements: `gh-pages` branch at repo root + a `.nojekyll` file (Jekyll would drop `_next/`). The deploy script handles both.

## Notes

- Search is client-side over the JSON file (72 records) — instant, but the payload ships to every visitor. Fine at this scale.
- Brand tokens (colors, typography, contact info) are centralized in `src/styles/tokens.css` and `src/lib/site.ts`.
- This is a public reference guide, not a diagnostic tool — no clinical claims beyond the published content.

## Design tokens (reference)

- `assets/css/design-tokens.css` is the **fixed reference** for global colors, borders, radius, shadows, and spacing (CarePlus Medical palette: turquoise `#1ba39c`, accent `#2d9cdb`, light cool backgrounds). It is imported in `src/app/layout.tsx`, so it links in the `<head>` of every page, and stays unedited — supplements live in `src/styles/`.
- `src/styles/tokens.css` maps the legacy tokens (`--brand`, `--border`, `--text-*`, radii, shadows) onto the reference variables, so the whole design follows the reference palette.
- The hero, the «طبيب»/«مريض» mode switch, the search card, and the chapter/case cards are built on the reference classes (`.hero-image-wrap`, `.hero-badge`, `.tab-group`/`.tab`, `.btn-pill`, `.search-input`, `.card`).
- The doctor hero image ships from `public/doctor-hero.png`; `scripts/hero-doctor.mjs` regenerates a placeholder (or copies your real photo) from `assets/images/doctor-hero.png` at prebuild — drop the final photo there with the same filename and rebuild.

## Doctor / Patient mode (Round 4)

- Two compact buttons — **طبيب** / **مريض** — sit under the site header (second row of the fixed nav on the home page, and under the header on case pages). Doctor is the default; the choice persists in `localStorage` (`rochetta-mode`). No overlay, no forced decision.
- **Doctor mode** (default): full clinical view — diagnosis, investigations, treatment, instructions, alternatives and raw interaction cards.
- **Patient mode**: simplified view — plain-language diagnosis/investigations tabs, alarm-signs card, rephrased interactions, larger type (17px/1.85), and a patient accent (`#2d9cdb`, the reference accent) applied to interactive elements only via the `--accent` token.
- Patient content is **authored manually** per record via optional fields; while empty, the UI shows neutral placeholders (no auto-generated clinical text):

  ```jsonc
  {
    "id": "rochetta-001",
    "patient_diagnosis_summary": "…",   // optional: plain Arabic explanation
    "patient_interactions_summary": "…", // optional: rephrased interaction note
    "alarm_signs_patient": ["…", "…"]    // optional: signs that should prompt a re-check
  }
  ```

- **Deferred (by decision, noted for later):** doctor/patient **lab-reading** (needs a serverless host; no API keys allowed in client) and **case ratings** (would need persistent storage). Neither ships in the current static export.
